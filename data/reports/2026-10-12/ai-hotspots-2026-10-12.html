事实分析与风险

GPT-6.1 Sol 在 Codex 与 Work 的默认上下文提升到 500k

OpenAI Codex 产品负责人 Tibo Sottiaux 宣布，GPT-6.1 Sol 通过 Codex 与 Work 使用时，默认上下文长度从 272k 提升到 500k，约增加 80%；用户仍可手动覆盖设置，模型最大上下文为 1M。官方给出的直接目的，是减少上下文压缩发生，并帮助长任务保留更多细节。

分析：长上下文正在从少数用户手动调参变成产品默认值。内容团队和代码 Agent 会更晚触发压缩，但更大的容量并不自动等于更好的检索、注意力分配或事实一致性。

风险：不能把默认 500k 写成 API 全面升级，也不能推断长任务质量必然提高；公告只明确 Codex 与 Work，且 1M 是可覆盖的最大值。

Gemini CLI nightly 修补提问丢失、工具拒绝串扰与目录递归读取

Google Gemini CLI 发布 v0.65.0-nightly.20261010：保留 ask_user 问题文本；让 A2A server 在顺序批次中只把工具拒绝作用于当前调用；跳过对 @<directory> 引用的急切递归读取；同时修复不受信任命令参数的误报、交互模式回车卡死、JSON 与流错误处理等问题。该版本是 nightly，不是稳定版。

分析：Agent 可靠性越来越取决于控制流细节：一次拒绝不能污染后续调用，向人提问时不能丢掉问题文本，引用目录也不应在任务开始前吞入全部文件。

风险：不能把 nightly 修复描述为稳定版新功能；Release 未披露影响范围、事故数量或性能收益。

State of AI Report 2026 把 Agent 的部分得分与完整完成率拆开

State of AI Report 2026 官方专题页指出，在 FrontierChallenge 的 97 个科学工作流中，GPT-5.6 Sol 对单项要求的得分为 87.9/100，但完整完成率为 20.6%；在 OSWorld 2.0 中，Opus 5 的部分得分为 77.7%，完整完成率为 44.3%。报告强调，不同评测的任务、完成标准与计算预算必须与模型名一起呈现。

分析：自媒体最容易把高分写成“任务已经做完”。这组数据提供了一个更实用的选题：Agent 看起来完成了大多数步骤，为什么最终交付仍可能失败。

风险：不得跨评测直接比较两款模型；87.9 与 20.6%、77.7 与 44.3%来自不同任务与计分体系。

默认上下文从 272k 涨到 500k：Codex 会少忘事，还是只是更晚压缩？

受众：Codex 与 Work 用户、AI 编程团队、长文研究者、Agent 产品经理

角度：把“默认值”与“最大值”分开讲，解释 500k 会怎样改变压缩频率、长任务成本和上下文工程，并给出不靠塞满窗口的实践清单。

结构：1. 500k 改了什么；2. 默认值为何比 1M 上限更影响普通用户；3. compaction 会丢掉哪些细节；4. 更大窗口仍可能出现的注意力稀释；5. 代码、长文和研究任务分别怎么受益；6. 何时仍应拆任务；7. 如何验证新默认值是否生效。

风险：公告来自产品负责人 X 帖，尚未在公开帮助中心看到同日独立条目；不要外推到 API，也不要承诺质量或速度提升。
